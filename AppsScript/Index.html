1. Mathematical Dynamic Corridor Impedance Formulation

Physical distance is insufficient during metropolitan disasters. DURGA evaluates road corridors dynamically using:

Cost(e) = TravelTime(e) × (1 + 1.5 × Congestion(e)) × (1 + 2.5 × Danger(e)) Where: - TravelTime(e) = Distance(e) / BaseSpeed(e) in seconds - Congestion(e) ∈ [0.0, 1.0] (vehicular density modifier) - Danger(e) ∈ [0.0, 1.0] (thermal/toxic hazard proximity modifier) - If a corridor is compromised/blocked, Cost(e) = ∞, ensuring Dijkstra bypasses it.

2. DAA Viva Examination Preparation Bank (Model Q&A)

Q1: Why does Dijkstra’s algorithm fail on graphs with negative edge weights?

Dijkstra relies on the greedy choice property: once a vertex u is extracted from the min-heap (settled), its shortest path distance is finalized and never relaxed again. If negative edges exist, a longer path could subsequent reduce the distance, violating the invariant. In DURGA, corridor weights are strictly non-negative, guaranteeing mathematical optimality.

Q2: How does Disjoint Set Union (DSU) achieve near-linear time O(E · α(V)) in Kruskal’s algorithm?

DSU combines two key optimizations: (1) Union-by-Rank, which attaches the shallower tree under the deeper tree to keep height O(log V); and (2) Path Compression, which points every traversed node directly to the root during Find(). Combined, any sequence of m operations runs in O(m · α(n)) time, where α is the inverse Ackermann function (α ≤ 4).

Q3: Why is 0/1 Knapsack Dynamic Programming called "pseudo-polynomial"?

The time complexity is O(N · W), where W is the numerical capacity. Because the input size of W is represented in log₂(W) bits, the runtime is exponential with respect to the input length. In municipal disaster dispatch, vehicle budgets (W ≤ 50) execute in sub-millisecond real time.
